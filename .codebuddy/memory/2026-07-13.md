# 2026-07-13

## 修复：Django admin 登录页无法显示（静态资源 404）

### 现象
访问 `http://localhost:8000/admin/login/` 时登录页“进不去正常界面”（实际是 simpleui 登录页的 CSS/JS 全部 404，页面无样式残缺）。

### 根因
1. 后端通过 `start_backend.bat` 用 **daphne**（ASGI）运行，daphne **不会**像 runserver 那样在 DEBUG 下自动提供 `/static/`，而 `urls.py` 只在 DEBUG 下映射了 `/static_files/`（与 simpleui 引用的 `/static/` 不一致）。
2. **`collectstatic` 从未执行**，`STATIC_ROOT`（`static_files/`）里没有任何静态资源。
3. nginx（`c:\nginx/conf/nginx.conf`）也没有 `/static/` 映射；且原配置中 `location ~* \.(js|css|...)$` 正则块优先级高于前缀 `location /static/`，会把 `/static/` 请求错误地指向 `frontend/dist/`。

### 修复
- `backend/urls.py`：新增 `urlpatterns += static(settings.STATIC_URL, document_root=settings.STATIC_ROOT)`，让 daphne 也能从 STATIC_ROOT 提供 `/static/`。
- 执行 `python manage.py collectstatic --noinput`（生成 2609 个文件到 `static_files/`）。
- `c:\nginx/conf/nginx.conf`：
  - `location /static/` 改为 `location ^~ /static/`（强制优先于正则静态资源块），`alias` 指向 `static_files/`。
  - 新增 `location /admin/` 代理到 `127.0.0.1:8000`（否则 80 端口的 /admin/ 被 SPA 的 `location /` 兜底成前端页面）。

### 验证
- `:8000/admin/login/` → 200 + 密码输入框存在；`/static/admin/simpleui-x/css/login.css` → 200
- `:80/admin/login/` → 200 + 密码输入框存在；`/static/...` → 200

### 注意（部署踩坑）
- nginx 重启必须用 `-p c:\nginx -c c:\nginx\conf\nginx.conf`，否则会从项目目录作 prefix 找 `conf/nginx.conf` 导致 reload 失败。
- 若 simpleui 升级或换版本，需重新 `collectstatic`。

### 补充：方案A 收尾（static_files 不入库）
- `.gitignore` 中 `static_files/img/` 改为 `static_files/`（整个目录忽略）。collectstatic 生成的 2609 个产物是运行时生成的，不应提交到版本库。
- 部署规范：新机器/新环境部署时，在 `pip install` 之后执行 `python manage.py collectstatic --noinput`。

### 权限加固：只有项目负责人能删除项目/用例/接口
- 原有逻辑：项目删除、测试用例删除、API 接口删除只有 `IsAuthenticated` 检查，任何登录用户都能删。
- 修改：所有删除操作统一检查 `instance.owner == request.user`（或项目 owner），非负责人返回 403。
- 涉及文件：
  - `apps/projects/helpers.py`：新增 `get_user_owned_projects(user)` 工具函数
  - `apps/projects/views.py:ProjectDetailView`：新增 `perform_destroy`
  - `apps/api_testing/views.py:ApiProjectViewSet`：`perform_destroy` 加 owner 检查
  - `apps/ui_automation/views.py:UiProjectViewSet`：`perform_destroy` 加 owner 检查
  - `apps/app_automation/views/project_views.py:AppProjectViewSet`：新增 `perform_destroy`
  - `apps/testcases/views.py:TestCaseDetailView`：新增 `perform_destroy`；`TestCaseBatchDeleteView` 改用 `get_user_owned_projects`
  - `apps/api_testing/views.py:ApiRequestViewSet`：`perform_destroy` 加 project owner 检查（通过 `collection.project.owner`）
