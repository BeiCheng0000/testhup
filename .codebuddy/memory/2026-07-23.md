## 自动化测试执行 171 接口超时修复
- **现象**：`POST /api/api-testing/test-suites/3/execute/` 执行 171 个接口卡顿/超时，Daphne 日志 `Application instance ... took too long to shut down and was killed`。

  - 前端 `AutomationTesting.vue runTestSuite`：发起执行后立即轮询 `GET /api-testing/test-executions/<id>/` 每 1.5s 直到 `COMPLETED`/`FAILED`，弹窗随轮询刷新。
- **附带修复**：`views.py` 第 1 行原先被损坏为 `modelsfrom rest_framework import ...`（语法错误，服务重启即崩），改为 `from rest_framework import ...`。

## 断言 falsy 值比较 bug 修复（expected=0 被当作未配置）
- **现象**：API 请求的断言配置了 `{"name":"code断言","type":"json_path","json_path":"$.code","expected":0}`，但执行报 `"断言失败: code断言 - 实际值=0, 期望值未配置"`，且前端显示断言数为 0。
- **根因**：`execute_assertions`(utils.py line 36) 及其他 3 处使用 `assertion.get('expected') or assertion.get('expected_value') or assertion.get('value')` 读取期望值。Python 中 `0 or None or None` → `None`（0 是 falsy），因此 `expected=0` 被当作缺失，比较 `str(0)==str(None)` 失败。
- **修复**（4 处）：
  - `apps/api_testing/utils.py`：`execute_assertions` 中 `json_path` 类型（~line 36）和 `header` 类型（~line 92）的 `expected_val` 改为显式 `is None` 判断。
  - `apps/api_testing/views.py`：`_run_test_suite_execution` 中 `suite_request.assertions` 的 status_code 手动检查（~line 927）同改。
  - `apps/api_testing/views.py`：`add_requests` 方法（~line 1144）原先创建 `TestSuiteRequest` 时 `assertions` 硬编码为 `[]`，改为 `copy.deepcopy(api_request.assertions)`；且对已存在但断言为空的记录自动回填。这样前端"显示断言数 0"的问题也一并解决。
- **待生效**：需 `taskkill /F /IM daphne.exe && start "" venv\Scripts\daphne -b 0.0.0.0 -p 8000 backend.asgi:application` 重启后端。已存在的测试套件需**重新添加接口**（或调用 `sync-assertions`）才能看到断言数更新。

## 测试套件执行卡在 RUNNING（线程死掉不落库）
- **现象**：执行跑到 80/170 后进度不再推进，状态一直 `RUNNING`，"半天没有动"。
- **根因**：后台线程长时运行期间 MySQL 连接可能被服务端回收（`wait_timeout`）。原代码每次 `execution.save()` 直接调用，遇 `OperationalError` 时：单次请求的 `except` 里再次 `save()` 也失败 → 抛到函数级 `except` → 函数级 `save()` 又失败且被 `except: pass` 吞掉 → 执行记录永远停在 `RUNNING`，daemon 线程静默死亡（异常不冒泡）。`requests.request(timeout=30)` 与 node `subprocess(timeout=30)` 都是 30s 上限，所以不是请求挂死，是 DB 连接挂死。
- **修复**（`apps/api_testing/views.py`）：
  - 新增模块级 `_safe_save_execution(execution)`：先 `save()`，失败则 `close_old_connections()` 后重试一次，再失败仅记日志不抛异常。
  - 循环每个迭代开头调用 `close_old_connections()` 强制用新连接，避免长事务连接被回收。
  - 将原 4 处 `execution.save()`（成功分支进度、异常分支进度、循环结束、函数级 except 的 FAILED）全部替换为 `_safe_save_execution`，保证执行最终一定落库为 COMPLETED/FAILED，线程不会卡死。
- **已生效**：本次已 `taskkill daphne` 重启（新 PID 4240）。并用 Django shell 把 `start_time` 早于 5 分钟且仍为 `RUNNING` 的执行记录标记为 `CANCELLED`（清掉卡死的 1 条：**TestExecution 模型没有 `error_message` 字段**，清理脚本不要用该字段）。curl 返回 401 确认服务正常。
- **注意**：`TestExecution` 模型字段不含 `error_message`（函数级 except 也不引用它）。若以后要存错误，需先加字段+迁移。
- **遗留建议（可选）**：每次部署/重启 daphne 都会杀掉在跑的 daemon 线程，遗留的 RUNNING 记录会卡死。可考虑在启动时扫一遍孤儿 RUNNING 标记为 CANCELLED（未实现）。

## 请求历史接口性能优化
- **问题**：`GET /api/api-testing/histories/?page=1&page_size=20&request__request_type=HTTP` 响应过慢。
- **根因**：
  1. 权限过滤 JOIN + `.distinct()` 开销大
  2. `select_related` 加载 6 个关联表
  3. 嵌套序列化器（ApiRequest + Environment + User）
  4. `request_data`/`response_data` JSONField 量大

- **优化**：
  1. **索引**（models.py）：`RequestHistory` 加 `executed_at`/`request` 索引；`ApiRequest` 加 `request_type` 索引

  3. **Exists 替代 JOIN+DISTINCT**（views.py）：权限改用 `Exists(OuterRef(...))`
  4. **Defer response_data**（views.py）：列表 `defer('response_data')`
  5. **精简 select_related**：只保留 request/environment/executed_by
  6. **get_serializer_class**：list 用轻量版，detail 用完整版
- **前端适配**：`HistoryTable.vue` 字段扁平化；`RequestHistory.vue` 详情改 API 重载
- **生效**：`npm run build` + Daphne 已重启

## 自动化运行时其他接口请求失败的修复
- **问题**：自动化测试套件运行期间，其他 API 请求（如请求历史等）会失败。
- **根因**：后台执行线程在 171 次循环迭代中，**每轮都调用 `close_old_connections()`**，频繁关闭/重建数据库连接，导致 MySQL 连接池饱和，其他请求线程拿不到连接。
- **修复**：
  1. **数据库配置**（`backend/settings.py`）：添加 `CONN_MAX_AGE=600`（持久连接存活 10 分钟）和 `CONN_HEALTH_CHECKS=True`（每次使用前检查连接是否存活），避免线程频繁创建/销毁连接。
  2. **线程连接隔离**（views.py `_run_test_suite_execution`）：线程启动时 `connection.close()` 彻底断开从父线程继承的连接，避免线程间共享连接。循环内改为**每 20 次迭代或每 60 秒**才调用一次 `close_old_connections()`，而非每次都关。
  3. **安全保存改进**（views.py `_safe_save_execution`）：从"重试 1 次"改为"指数退避重试 3 次"（0.3s→0.6s），提高 MySQL 短暂波动时的容错能力。
  4. **定时任务线程同样修复**（views.py `_execute_task_async` 的 `execute()`）：添加 `connection.close()` + 去除冗余 import。
- **生效**：需重启 Daphne（`taskkill /F /IM daphne.exe` → 重新 `start "" daphne ...`）。
