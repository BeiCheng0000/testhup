## Agent 设备测试执行双方案实现

### 背景
用户要求实现 Agent 代理设备的测试用例执行功能。之前 Agent 设备只能用于截图/UI层级等实时操作，无法执行测试（因为 Airtest 不认识 `agent:host_id:local_device_id` 格式）。

### 方案A: 直接 TCP 连接
**原理**: Agent 已在设备上启用 TCP 调试 (`adb tcpip 5555`)，设备 IP 存储在 AppDevice 表中。直接从主服务器通过 TCP 连接设备。

**实现**:
- `apps/app_automation/utils/agent_device.py` — 新建工具模块
  - `is_agent_device()`: 判断设备ID格式
  - `parse_agent_device_id()`: 解析 `agent:host_id:local_device_id`
  - `resolve_tcp_device_address()`: 从设备记录获取 IP:Port
  - `check_tcp_reachable()`: TCP 连通性检查
  - `get_execution_strategy()`: 统一策略入口
- 修改 `tasks.py`: 执行前解析设备ID，将 `agent:xxx:xxx` 转为 `192.168.1.100:5555`

### 方案B: Agent 远程执行
**原理**: 通过 WebSocket 将测试配置发送给 Agent，Agent 在远程主机用 Airtest 本地执行测试，结果打包回传。

**WebSocket 协议新增消息类型**:
1. `exec_command {command_type: "run_test", ...}` — Server→Agent 执行请求
2. `test_progress` — Agent→Server 进度更新
3. `command_result` — Agent→Server 完成结果（含 Allure 结果 zip base64）

**修改文件**:
- `adb_agent.py` — 新增方法:
  - `_cmd_run_test()`: 处理远程测试执行
  - `_sync_connect_device()`: Airtest 连接设备
  - `_sync_execute_step()`: 执行单个UI Flow步骤（支持 click/swipe/input/wait/back/home/app_start/app_stop/assert_*）
  - `_send_progress()`: 发送进度到服务器
  - 模块级: `_write_allure_result()`, `_write_allure_step_result()`, `_pack_allure_results()`
- `consumers.py` — 新增 `_handle_test_progress()`: 接收进度并转发至 execution WebSocket 组
- `tasks.py` — 新增:
  - `_execute_via_agent()`: 通过 agent_registry 发送命令并等待响应
  - `_save_agent_allure_results()`: 解压 Allure 结果到本地
  - `_get_server_base_url()`: 获取服务器 URL

### 策略选择与回退
- `settings.py` 新增 `AGENT_EXECUTION_STRATEGY` 配置:
  - `'auto'`（默认）: TCP可达→方案A; 不可达→方案B
  - `'direct_tcp'`: 强制方案A
  - `'agent_remote'`: 强制方案B
- 自动模式下自动回退，无需手动切换
